# InSoulForge 前端 UI／UX 设计规范

本文用于管理后台后续功能开发、界面修改和代码评审，统一组件选型、交互行为、视觉表达与验收方式。适用范围为 `frontend/` 中的 Vue 页面和共享组件。

本文是后续开发的设计依据，不代表现有页面已全部符合要求，也不要求为采用本文而批量重构。新增功能按本文设计；修改已有功能时，优先完善本次涉及的交互。

## 1. 规范级别与基本原则

- **必须／不得**：交付要求，涉及任务正确性、状态反馈、数据保护和基本可访问性。
- **优先／建议**：默认设计方案；有明确的空间、业务或平台约束时可以调整，并在变更说明中记录原因。
- 本文中的选项数量、间距和尺寸建议是项目约定，不是所有产品通用的硬性标准。

设计时按以下顺序判断：

1. 用户能否看懂当前页面的用途、作用对象和操作后果。
2. 用户能否直接发现主要选项，以尽量少的操作完成任务。
3. 用户能否避免误操作，并在出错后恢复。
4. 页面是否与项目其他页面保持一致。
5. 视觉效果是否帮助理解，而非增加干扰。

不要只因为组件库提供了某个组件就使用它；先判断用户是在选择值、切换内容、执行动作，还是修改状态。

## 2. 组件选型

### 2.1 选择控件

| 用户意图 | 优先组件 | 适用条件与说明 |
| --- | --- | --- |
| 少量选项中选一个 | 单选框 Radio | 选项需要同时可见，特别是标签较长或需要附带说明时 |
| 少量短选项中选一个 | 分段选择器 Segmented Control | 通常为 2～4 项，表达同一维度，各项能在可用宽度内完整展示 |
| 较多选项中选一个 | 下拉选择框 Select | 展开可以节约空间；不要为了统一外观把所有选择都做成下拉框 |
| 大量选项中查找一个 | 可搜索选择框 Combobox | 如模型、人员或工具列表；支持无结果、清空及键盘选择 |
| 选多个独立项目 | 复选框 Checkbox | 明确是否有数量限制；“全选”需要表达部分选中的状态 |
| 立即开启或关闭功能 | 开关 Switch | 修改后立即保存，适用于“启用／禁用”等布尔状态 |
| 随表单一起提交布尔值 | 复选框 Checkbox | 在点击“保存”后生效，避免与立即生效的开关混淆 |
| 切换同层级内容面板 | 标签页 Tabs | 如不同配置面板；不用于代替表单值的选择 |
| 触发一个动作 | 按钮 Button | 如保存、添加、重试；跳转到地址使用链接 |

数量只是辅助判断。两个选项并非绝对不能用 Select，但空间充足、标签简短且需要比较时，应优先直接展示。不得把“群聊／私聊”这类类别选择做成开关。

### 2.2 选中状态与默认值

- 必须清晰区分已选、未选、禁用与焦点状态；不能只靠颜色变化表达选中。
- 仅在存在合理且低风险的常用值时预选；需要用户主动判断的重要选项应要求显式选择。
- 不得默认开启高成本、扩大权限或不可逆的行为。
- 切换选项后，相关字段标签、提示和校验规则必须同步变化。
- 隐藏字段不得阻止当前表单提交，也不得携带与当前选择冲突的数据提交。
- 对仍然有效的输入尽量保留；必须清除时避免无提示地丢失大量已填内容。

## 3. 页面结构与信息层级

- 一个页面围绕一个主要任务组织，标题描述业务对象或用途。
- 页面头部放标题和主要操作；搜索、筛选靠近其作用的列表；行操作靠近对应记录。
- 同一操作区域通常只有一个视觉突出的主按钮。危险操作与高频操作保持距离。
- 相关字段放在同一组，组内间距小于组间间距；通过标题与留白表达层级。
- 重要状态、操作后果和必要输入要求直接展示；低频高级配置可折叠。
- 不得把完成任务必需的信息只放在悬停提示中。
- 长配置表单应按业务分组；需要独立保存时，明确每个保存按钮的作用范围。

## 4. 表单与输入

### 4.1 标签与提示

- 每个输入控件必须有可见标签；使用 `label` 与控件关联，成组选择优先使用 `fieldset` 与 `legend`。
- Placeholder 只用于举例或补充输入提示，不能替代标签。
- 执行配置页的分组标题使用次级文字色并保留加粗，同组相邻配置行通过限制在配置内容宽度内的淡线区分，组间继续使用色块和留白。数值输入框采用 36px 高度，底色略微贴近配置区域并保留清晰边界；数值范围在输入框聚焦时显示，校验错误直接展示；布尔配置保留简短影响说明，详细机制通过说明图标悬停、聚焦或点击查看，可用 Escape 收起。保存提示统一放在保存按钮旁；值发生变化时显示“有未保存的修改”，改回已保存值或成功保存后清除，保存失败时保留。详细说明浮层使用与配置区域明显区分的背景和清晰边界，并兼顾浅色、深色主题。
- 模型配置沿用执行配置的分组、行式排列、36px 控件、聚焦范围提示、详细说明图标和未保存状态；文本输入保留适合地址、路径和模型名称的宽度，缓存键复选框放在行右侧。生图重试可能重复生成并计费等重要影响保持可见，默认模型与备用模型仍独立保存。
- 记忆与上下文配置沿用执行配置的独立圆角分组、单行排列、36px 数值输入、聚焦范围提示和未保存状态；好感度复选框放在右侧，详细机制通过说明图标查看，删除旧消息、关闭功能和篇幅可能超限等重要影响保持可见。
- OneBot 配置沿用逐行排列、36px 控件、独立圆角分组和未保存提示；详细说明按需查看，服务匹配要求与当前运行方式保持可见。切换传输方式后显示待保存的目标，成功保存后才更新当前运行方式。
- 必填和选填的标识方式在同一表单中保持一致；必填标记必须能被理解。
- 单位直接写在标签或固定附加文字中，如“请求超时（秒）”。
- 格式、范围、费用或生效时机等影响填写的信息应提前说明。
- 用用户熟悉的业务名词，不向普通用户暴露内部字段名、枚举或实现术语。

### 4.2 输入行为

- 根据含义选择输入类型和输入法提示。用户 ID、群号等标识符使用字符串处理，建议使用文本输入搭配 `inputmode="numeric"`，避免数值增减和精度问题。
- 数值配置必须明确单位、范围及是否允许小数，并与服务端约束保持一致。
- 可安全处理的首尾空格可以自动去除；密钥、提示词、脚本等内容不得随意改写。
- 不阻碍用户输入尚未完成的合法中间状态；粘贴与键盘输入都应正常工作。
- 前端校验用于改善体验，服务端仍必须校验输入与权限。

### 4.3 校验与提交

- 初次展示空表单时，不立即显示一片错误；通常在失焦或提交后校验。
- 错误必须定位到相关字段，并说明修正方式，例如“请输入群号，仅支持数字”。
- 字段错误使用 `aria-invalid`，说明或错误通过 `aria-describedby` 关联；提交失败后聚焦首个错误字段或错误摘要。
- 错误不得只通过红框表达；失败后保留用户输入。
- 提交期间必须防止重复请求，并显示“保存中…”等状态；不能只把按钮变灰而不解释。
- 不得让用户猜测按钮为何不可用。未满足条件时提供说明，或允许提交后展示校验错误。
- 使用语义化表单和提交按钮；多行输入中的 Enter 保持换行，不触发意外提交。

## 5. 按钮与操作文案

- 文案使用具体动词和必要对象，如“添加会话”“保存配置”“清空记录”。
- 普通确认避免只有“确定”“是”；需要同时添加并启用时可写“添加并启用”。
- 主操作使用主题主按钮，次操作使用中性按钮，危险操作使用危险样式。
- 颜色含义保持一致：成功、警告、危险不能随页面任意改变。
- 纯图标按钮必须有可访问名称；不易理解的图标同时提供可见文字或提示。
- 保存、删除等操作使用按钮，导航使用链接；不得用可点击 `div` 代替原生控件。
- 行内多个操作保持顺序一致；低频操作可收入更多菜单，高频动作保持可见。

## 6. 模态对话框

### 6.1 适用范围与布局

- 用于短而集中的任务，例如添加会话、编辑名称或确认清空。
- 长流程、大量配置及需要频繁参考背景内容的任务，优先独立页面或侧栏。自定义工具的新增和编辑使用独立编辑页，短任务如导入、修改内置工具描述仍可使用弹窗。
- 标题说明任务，正文提供必要字段，底部统一排列次操作与主操作；本项目默认次操作在左、主操作在右。
- 提供可见的关闭方式；顶部关闭与底部取消的行为保持一致。
- 避免多层模态嵌套；内容过长时正文内部滚动，标题和操作仍应容易找到。

### 6.2 焦点与关闭

- 打开后将焦点移入对话框；简单表单可聚焦首个输入，危险确认优先聚焦安全操作。
- Tab 和 Shift+Tab 必须在对话框内循环；背景不能接收点击或键盘操作。
- 关闭后焦点回到触发控件；触发控件已不存在时移到合理的后续位置。
- 使用原生 `dialog` 或完整实现模态行为；自定义实现提供 `role="dialog"`、`aria-modal="true"` 和关联标题。仅添加 ARIA 属性不等于实现模态。
- 默认支持 Escape 关闭。存在未保存修改时，关闭操作进入统一的放弃修改流程；点击遮罩不得无提示地丢失内容。
- 提交中不得把“关闭窗口”伪装成“取消服务端操作”。需要阻止关闭时显示原因，且不得让界面无限停留在不可退出状态。

模态行为参考 [W3C APG Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

## 7. 异步状态与反馈

手机端操作通知放在顶部标题栏下方，并避开设备安全区域，不占用底部导航位置；桌面端继续显示在右下角。

| 状态 | 必须表达的内容 | 建议处理 |
| --- | --- | --- |
| 首次加载 | 正在获取数据 | 加载提示或骨架屏，避免先闪出“暂无数据” |
| 后台刷新 | 当前内容仍可用，正在更新 | 保留列表、筛选及滚动位置，不整页闪烁 |
| 空数据 | 尚未创建内容 | 说明用途并提供创建入口 |
| 无搜索结果 | 当前条件没有匹配项 | 提供修改条件或清除筛选入口 |
| 加载失败 | 数据未能获取 | 显示可理解的原因并提供重试 |
| 提交成功 | 目标操作已完成 | 更新实际状态，必要时显示简短成功提示 |
| 提交失败 | 操作未完成或结果不确定 | 保留输入并提供可执行的下一步 |
| 连接中断 | 实时数据可能过期 | 显示重连状态，避免继续显示为实时连接正常 |

- 成功提示可短暂展示；需要处理的错误不得仅依赖很快消失的 Toast。
- 不要把失败显示成空列表，也不要在刷新失败时清空已成功加载的数据。
- 开关立即保存时显示处理中状态；保存成功后确认新值，失败时保留或恢复已确认值，并说明原因。
- 搜索与筛选请求必须防止旧响应覆盖新结果；离开页面后清理轮询、订阅和无用请求。
- 超时不一定代表服务端未执行。涉及生成、发送或计费的操作，不得直接诱导用户反复重试；应先核实结果或提供幂等机制。

## 8. 危险操作与未保存内容

- 按影响决定是否确认，不对普通操作反复弹窗。退出登录必须先显示确认框，默认聚焦“取消”；未保存修改的后果合并在同一个框内说明。取消时不发送请求，退出成功后才返回登录页；请求失败时保留页面与草稿并允许重试。
- 不可逆或影响范围大的操作必须明确对象、范围与后果；高频且可恢复的操作可优先提供撤销。
- 确认按钮直接描述动作，如“清空当前会话记录”。取消按钮保持清晰可见。
- 必须区分清空后台记录、撤回平台消息、禁用会话和删除配置，不能用含糊的“删除”混称。
- 离开有未保存修改的表单时，提供保存、放弃或继续编辑的适当路径。
- 凭据默认遮挡，按需查看；显隐操作使用输入框右侧内嵌的眼睛图标按钮，保留显示／隐藏的可访问名称、悬停提示、按下状态和键盘焦点，输入文字不得被图标遮住；不得在提示、日志或错误详情中泄露密钥和令牌。

## 9. 视觉与主题

### 9.1 复用项目样式

- 主题变量以 `frontend/src/style.css` 为统一来源；组件优先使用现有 `.btn`、`.form-input` 等样式。
- 全局强调色通过侧栏底部进入独立的“主题配色”页面配置，支持预设与自定义 HEX 颜色，立即生效并保存在当前浏览器；恢复默认时清除自定义覆盖。`src/utils/theme.ts` 根据主题表面自动生成文字、按钮、悬停、选中底色和焦点颜色，深浅模式切换时重新计算，保证文字和控件对比度。成功、警告、危险及分类图表颜色保留独立含义；页面不得硬编码品牌强调色。
- 手机与桌面展示分别由 `src/mobile/`、`src/desktop/` 装配；已拆分页面不得再通过 `mobile` 参数切换视图，共用业务逻辑位于 `src/shared/features/`，不得导入页面组件。未重写页面仅从显式过渡清单接入。
- 优先复用已有共享组件；业务页面放在 `src/features/`，通用组件放在 `src/components/`。
- `EnabledSwitch.vue` 可用于立即保存的启用状态；父组件负责保存结果和失败反馈。
- `SlidingTabs.vue` 用于切换内容面板，通过 `idPrefix` 提供唯一标识，面板内容放在 `panel` 插槽中。它统一维护 tablist、tab、tabpanel 的关联和焦点：左右方向键、Home、End 移动焦点，Enter 或空格激活。需要确认放弃修改时，由父页面决定是否接受切换。表单值选择使用原生 radio，不复用标签页组件。
- 不在单个页面重新定义一套品牌色、按钮或输入框；新增通用设计变量时统一维护。
- 顶部页头、侧栏头部、导航和底部操作区统一使用 `--bg-sidebar`，作为连贯的界面框架底色；内容区和卡片使用各自的背景变量。
- 页面区域采用与页面背景略有差异的中性色块，配合留白区分层级，不再使用装饰性实线分隔区域；浅色和深色主题均复用主题背景变量。输入控件边界、焦点、选中状态及数据表格行线按其用途保留。
- 首页运行概况的标题、指标和内存趋势图放在同一个圆角卡片色块内，复用统一卡片背景、内边距和区域间距。
- 上下文占用页的组成说明和估算细节默认收起，通过说明图标悬停、聚焦或点击查看；保留统计范围、数值单位、占比、警告以及“预估值，非实际计费用量”的简短提示。组成区域按内容自然撑开，不为填满视口拉伸单项高度，每个组成部分独占一行，左侧显示名称与说明入口，右侧依次显示占用条、占比和 Token 数值；窄屏时上下排列。
- 采用简洁、现代圆角、低阴影的视觉方向；圆角统一使用 `frontend/src/style.css` 中的 `--radius-*` 变量：小型标记和复选框 4px、输入框和按钮 8px、卡片和内容区域 12px、弹窗 16px。开关轨道使用胶囊圆角；头像与状态圆点保留圆形。
- 侧栏底部的退出、配色、模式操作按此顺序在桌面上横向排列为紧凑的图标按钮组，不均分整行宽度，保留提示文字和可访问名称；窄侧栏纵向排列以保证点击尺寸。
- 侧栏导航和标签页通过圆角底色与文字强调表达选中状态，不再附加左侧色条或底部强调线；键盘焦点轮廓继续保留。
- 手机运行日志页的范围与级别并排、关键字独占一行；日志列表保留独立滚动及足够高度，不受筛选区挤压，以维持加载更早与自动跟踪行为。
- 独立手机首页按运行状态、四项关键指标、常用功能、详细信息排序；功能入口采用带图标的紧凑分组列表，内存监控、模型与资源明细默认收起，不把桌面监控卡片直接堆到手机首屏。
- 独立手机会话视图使用紧凑列表和独立详情；列表只展示身份、消息数与启用状态，开关及各项管理操作放在详情，聊天记录使用手机专用布局，不复用桌面会话表格。
- 手机人物页按自然页面高度排列列表与详情，列表最多显示约四行并局部滚动，避免按剩余视口比例压缩列表；详情操作按钮按两列排列，不产生横向溢出。
- 人物列表通过柔和的主题底色与姓名加粗、强调文字色表达选中状态，悬停底色弱于选中底色，不再使用左侧色条；键盘焦点轮廓向内绘制，避免被滚动容器裁切。
- 分段选择保留原生 radio 语义，视觉使用文字、勾号、底色和圆角边界，不直接展示平台圆点。复选框统一为小圆角方框，仍保持随表单保存的语义。
- 下拉框、数字输入和文件选择按钮使用统一主题样式，保持圆角尺度一致，避免系统蓝色混入界面；保留原生键盘操作及高对比度模式支持。
- 装饰性空状态和操作图标使用统一的线性 SVG，不使用彩色 Emoji 充当界面图标。

主题颜色按用途选择：

- `--text-primary`、`--text-secondary`、`--text-light` 分别用于正文、次要信息和辅助说明；辅助文字仍需满足普通文字对比度，不能再叠加透明度弱化。
- `--primary` 用于强调文字和图形；实底主按钮使用 `--primary-strong` 配合 `--on-primary`。深色主题的强调文字色较亮，不可直接用作白字按钮底色。
- 状态文字使用 `--success`、`--warning`、`--danger`；白字状态按钮分别使用对应的 `--*-btn`，不能混用文字色与按钮底色。
- 输入边界使用 `--control-border`，键盘焦点使用实色 `--focus-ring`；`--border` 可继续用于装饰性分隔线。
- 已禁用的会话记录仍包含可操作按钮和需阅读的信息，不对整行设置低透明度。真正不可操作的禁用控件可保留禁用样式。
- 修改主题变量时运行 `npm --prefix frontend test` 中的对比度回归检查，并分别检查两种主题的实际显示。自动检查覆盖既定颜色组合，不能替代完整界面验收。

### 9.2 排版与间距

以下是新增界面的建议尺度，已有相邻组件优先保持一致，统一调整时集中修改：

| 项目 | 建议 |
| --- | --- |
| 正文 | 14px，行高约 1.5 |
| 标签与辅助文字 | 12～14px，不能为了弱化而牺牲可读性 |
| 常用间距 | 4、8、12、16、24、32px；根据层级选择 |
| 字段间距 | 通常 16px，分组之间适当增加 |
| 常规操作控件 | 高度约 36～44px；触摸场景优先至少 44px |
| 动效 | 通常 150～250ms，用于表达状态变化 |

- 相同级别标题、字段和按钮保持一致，避免一个页面使用过多字号或强调色。
- 图标与文字对齐，按钮可点击区域包含完整视觉区域。
- 长名称、URL、模型名和错误消息必须可换行或截断；截断后仍提供获取完整信息的方式。
- 浅色和深色主题必须分别检查；不得假定已有变量在任意背景上都满足对比度。
- 重要辅助说明不要直接依赖低对比度的 `--text-light`；根据实际背景验证后选用适当变量。
- 支持 `prefers-reduced-motion`，减少非必要动画；不用持续闪烁或大幅位移吸引注意。

## 10. 响应式与可访问性

- 页面应在窄屏、桌面和浏览器放大时保持主要任务可完成，不依赖固定桌面宽度。手机（不超过 760px）逐步迁移至独立展示组件：底部使用首页、会话、人物、设置四个入口，详情页显示返回入口并隐藏底部导航，切换页面仍执行未保存保护。手机内容控件优先 44px 点击高度，输入文字至少 16px，减少卡片留白；桌面维持原布局。
- 表单在窄屏优先单列，按钮可换行或纵向排列；弹窗不得超出可视区域。
- 桌面视口（宽度至少 1100px）下，列表和顶部标签优先适配内容区宽度；表格列宽自适应，长名称、表头和数值允许换行；会话操作列在内容区宽度足够时按实际内容分配宽度，优先一行展示，空间不足时才换行，不依靠隐藏溢出裁掉内容。窄屏表格和标签可在局部横向滚动；不要让整页因单个长字段横向溢出。
- 所有操作必须可通过键盘完成，焦点顺序符合阅读顺序，焦点样式清晰且不被遮挡。
- 不移除浏览器焦点轮廓，除非提供同样清晰的替代样式；不使用正数 `tabindex` 强行重排。
- 普通文字与背景对比度至少 4.5:1；符合大字号定义的文字至少 3:1。项目 14px 正文按普通文字要求检查，不能只降低透明度来表达辅助层级。
- 自定义控件的必要边界、状态指示及焦点指示应清楚可辨；相关非文本对比度要求按 WCAG 1.4.11 检查。
- 点击目标默认至少 24×24 CSS px；WCAG 2.5.8 对间距、行内链接等存在例外，不能把 24px 当作舒适触控尺寸，触摸场景仍优先 44px。
- 状态和错误同时使用文字、图标或形状表达，不只依赖红绿颜色。
- 动态成功状态可使用 `role="status"`；重要即时错误按需使用 `role="alert"`，避免重复播报和把频繁刷新的日志整体设为警报。

以上对比度和点击目标要求参考 [WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[WCAG 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) 和 [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。这份清单不等于完整的 WCAG 合规评估。

## 11. 本项目示例：添加会话

以下为后续实现的推荐设计，不表示现有代码已完成调整。

```text
添加会话                                      ×

会话类型
[ 群聊 ] [ 私聊（已选） ]

用户 ID
[ 输入对方的 用户 ID                         ]
添加后立即启用，后续消息将按私聊处理。

                         [ 取消 ] [ 添加并启用 ]
```

- “群聊／私聊”是互斥的类别值，优先采用原生单选语义的分段选择器。
- 群聊显示“群号”和相应说明，私聊显示“用户 ID”和相应说明。
- 是否预选类型根据入口上下文决定，不因视觉需要强制预选。
- 点击“添加并启用”后显示“添加中…”，阻止重复提交。
- 校验失败定位到对应字段；请求失败保留输入；成功后更新列表并展示实际启用状态。
- 关闭、Escape、遮罩点击及焦点恢复遵循模态规则。

## 12. 开发与评审检查表

根据本次修改涉及的范围检查；不涉及的项可标记为不适用。纯文档修改无需运行前端构建。

- [ ] 组件符合用户意图，少量短选项无需额外展开即可比较。
- [ ] 标签、单位、作用范围、生效时机和操作后果明确。
- [ ] 默认值合理，切换选项后字段与校验同步。
- [ ] 主次按钮清晰，文案描述具体动作。
- [ ] 加载、空数据、无结果、成功和失败状态已覆盖。
- [ ] 重复点击、慢请求、失败重试及旧响应不会产生错误状态。
- [ ] 失败保留输入，关闭不会意外丢失修改。
- [ ] 键盘可完成任务，模态焦点进入、循环和恢复正确。
- [ ] 浅色与深色主题、窄屏、长文本及浏览器放大已检查。
- [ ] 可见标签、错误关联、对比度和点击区域满足要求。
- [ ] 复用项目主题和组件；偏离建议时已说明具体原因。
- [ ] 涉及前端实现时完成相关类型检查、构建和必要的交互验证；自动测试重点覆盖校验、请求状态、数据保留等容易回归的行为。
