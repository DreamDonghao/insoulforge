# MCP 客户端

InSoulForge 可通过 HTTP MCP 服务发现并调用远程工具。无需部署 MCP 服务端，
也不需要 Python 或其他 MCP SDK。当前只支持 Streamable HTTP 的工具查询和调用。

## 配置

运行目录的 `data/config.json` 新增 `mcp` 字段；旧配置启动时自动补充空服务列表。
默认不连接任何外部服务。后台的“MCP 服务”页面支持新增、编辑、启用/禁用、删除和刷新工具。
后台保存后立即生效，无需重启；直接编辑文件仍需重启后读取。

```json
{
  "mcp": {
    "servers": [
      {
        "name": "deepwiki",
        "description": "查询公开 GitHub 仓库的文档、架构和代码相关问题",
        "url": "https://mcp.deepwiki.com/mcp",
        "token": "",
        "enabled": true,
        "timeoutSeconds": 30
      }
    ]
  }
}
```

将 `mcp` 加到原配置中，不要用以上片段覆盖整个文件。
只配置可信服务：远程工具可能读取或修改其服务端数据，机器人会把模型生成的参数发送给该服务。
不要在 URL 中填写凭据，认证信息放在 token 或 headers 字段。

字段说明：

- `name`：唯一服务名称，1 至 20 个英文、数字、下划线或连字符，用于工具命名。
- `description`：可选用途描述，最多 1024 UTF-8 字节，供模型选择服务。旧条目缺省按空字符串读取，保存时补充。
  仅修改描述不重新连接或清除缓存，下一次回复使用新描述；未填写时目录只列名称。
- `url`：完整 HTTP(S) MCP 地址，路径保留并与 HTTP origin 分开处理。
- `token`：可选 Bearer Token，默认空字符串。
- `headers`：可选自定义请求头对象，默认 `{}`，值必须是字符串。后台可逐项添加、编辑和删除，值以密文输入。
  例如 TinyFn 使用 `"headers": {"X-API-Key": "你的密钥"}`，此时 `token` 留空。
  名称不区分大小写且不能重复，不允许覆盖 MCP 协议头、Host、Content-Type、Accept 等保留头；
  配置 token 时不能再配置 Authorization 请求头。配置文件中的认证信息仍以明文保存，请限制文件访问权限。
- `enabled`：可选，默认 true；false 的服务不连接。
- `timeoutSeconds`：每次 HTTP 请求的超时，默认 30 秒，允许 1 至 120 秒。

最多配置 16 个服务。无效的启用配置会在启动或后台保存时报告错误；网络不可用不会阻止机器人启动。
启用和禁用的服务都需填写有效且唯一的名称及地址。地址不允许内嵌凭据、空白字符或片段，
端口必须在 1 至 65535 之间；认证令牌不能包含空白和控制字符。

## 工具如何使用

MCP 网络请求也显示在后台“请求调试”中，标签为 `MCP:服务名称`。
记录初始化、初始化通知、工具目录分页、工具调用及会话关闭的请求体、HTTP 状态和响应体；
工具执行关联触发的会话 ID，后台工具发现不关联群聊。未收到响应时状态为 0，并显示具体网络错误。
认证请求头不写入记录；JSON 中的图片数据省略，超出响应大小限制的响应只记录错误说明。
记录与其他 HTTP 请求共用最近 50 条内存缓存，重启清空，不写入数据库。

后台保存配置后，或模型首次查询某个服务时，客户端初始化会话、请求 tools/list、遍历分页并缓存工具定义。
成功加载后不在每次回复时重复查询。后台新增或启用服务后自动发现，修改地址、令牌或请求头后重新加载。
“刷新工具”会重新查询全部启用服务，刷新失败保留此前工具，并显示具体错误。
无缓存时只加载模型选中的服务，不在回复前加载所有服务。加载失败后 60 秒内不重复请求。
正在加载且没有缓存时返回明确状态，不用空列表掩盖错误；有原缓存时仍可查询它。
首次发现可能增加回复等待时间，每服务最多 256 个工具、20 页。

Executor 的 system 提示词包含已启用服务的简短目录，不包含 URL、令牌或完整工具定义。
模型默认只获得原有内置/Lua 工具，以及以下两个 MCP 管理工具：

1. `mcp_list_tools(server, query?, cursor?)`：查询指定服务的工具名称与说明。query 按名称或说明做关键词匹配，
   英文大小写不敏感。说明最多 512 UTF-8 字节，不含参数 Schema。分页游标绑定查询和缓存版本，变化后需重新查询。
2. `mcp_enable_tools(server, names)`：按远程名称启用当前回复所需的工具，返回实际调用名称。
   完整参数 Schema 从下一轮模型请求的 tools 字段开放，不在启用结果中重复发送。

例如先查询 `deepwiki`，再启用 `read_wiki_structure`，下一轮才能调用：

远程工具 `read_wiki_structure` 在服务 `deepwiki` 下注册为：

```text
mcp_deepwiki_read_wiki_structure
```

每次回复拥有独立选择状态，群聊之间和不同回复之间不共享启用状态。
后端校验本轮确实开放的工具及版本，同一轮先启用再调用新工具会被拒绝。
重复启用不额外占用名额；未知名称或超限时整批拒绝，不部分启用。
查询、启用和执行沿用现有模型迭代轮数限制。最后一轮只开放回复工具，两个 MCP 管理工具也不能执行。
没有启用服务时，不注入目录，不开放管理工具。

后台“执行配置”页可设置以下参数，回复开始时读取快照，修改仅影响后续回复：

| execution 字段 | 默认值 | 范围 |
|---|---|---|
| mcpToolPageSize | 10 | 1～50 |
| mcpMaxToolsPerEnable | 4 | 1～20 |
| mcpMaxToolsPerReply | 12 | 1～64 |

三个字段均为整数，单次启用上限不能超过本次回复总上限。旧配置自动补充默认值；无效文件配置在启动时修复，后台无效保存被拒绝。

本地名称上限 64 字符，远程名称须适配英文、数字、下划线或连字符；不兼容的服务明确加载失败。
注册是按服务原子提交的，工具名冲突不会覆盖其他插件的工具。
删除、禁用或修改服务会立即卸载对应旧工具；已经开始的调用允许完成，不再接受新调用。
发现期间删除或修改服务，旧发现结果不会将旧工具重新注册。保存失败不修改配置或运行时工具。
服务删除、禁用或连接配置修改后，旧回复中的选择不能用于新服务。工具定义刷新变化后必须重新启用；
刷新失败或定义未变化时，原缓存版本和授权仍有效。
页面显示服务加载状态、工具数量和最近错误。工具数量表示已缓存定义，不代表持续保持连接。

每次调用新建并初始化独立会话，完成后尝试 DELETE 关闭，因此不同群聊不会争用 Client。
这会增加握手开销，也不保留跨调用的服务端会话状态；以后可改为按事件循环维护会话池。
不自动重试 tools/call，避免远程副作用重复发生。

请求失败的具体错误返回模型；有效结果完整保留 content、structuredContent 和 isError。
图片或音频 content 当前以 JSON/base64 文本交给模型，不会自动作为消息附件发送。
关闭失败只记录警告，不会把已经成功执行的工具当作失败或重新执行。

## 已知限制

- 当前 SSE 在完整 HTTP 响应结束后解析，不支持长期保持连接、增量通知、断线恢复。
  服务器不结束响应会导致请求超时，不能宣称兼容所有 Streamable HTTP 服务。
- 不开启 GET SSE 流；服务器主动请求明确报错，普通通知跳过。
- 不支持 stdio、旧版 HTTP+SSE、OAuth、resources、prompts、sampling、roots、elicitation。
- 请求超时不代表远端工具停止；尚未实现主动取消。
- 每响应最多解析 1 MiB，但限制在接收完成后检查，不是接收阶段内存上限。
- 会话过期时客户端报告错误并清理状态，机器人不会重放失败调用。
- 暂不提供按群服务授权和管理员工具白名单；服务目录对所有会话可见，具体工具需由每次回复独立选择。

## 管理接口

以下接口沿用管理后台登录认证：

- `GET /admin/api/mcp-config`：返回服务配置和 status，响应禁止缓存，令牌仅供已登录管理员编辑。
- `POST /admin/api/mcp-config`：提交 `{ "servers": [...] }`，先持久化再生效，异步启动工具发现。
- `POST /admin/api/mcp-config/refresh`：重新发现工具，返回各服务的 status。请求成功不意味着所有服务加载成功，应检查 status.error。

后台保存时附带 `originalServers`，即加载页面时读取的原始服务列表。
列表已被其他页面修改时返回 HTTP 409，保留现有配置和工具，重新加载页面后再保存。
程序化调用可以省略此字段，但此时由调用方负责避免并发覆盖。

## 代码与测试

- `include/infrastructure/mcp` / `src/infrastructure/mcp`：独立协议及 HTTP 客户端，保留 `drogonmcp` 命名空间，方便后续抽离。
- `agent/tools/mcp/McpTools`：配置校验、发现缓存和 ToolRegistry 适配，不把业务规则放进协议层。
- `agent/tools/mcp/McpToolSelection`：请求级目录、配置快照和选择状态；ToolQuery 筛选定义，ToolCallContext 携带本轮授权。
- `tests/manual/McpClientExample.cpp`：终端交互式手动测试程序，不加入自动测试。
- `tests/McpClientTests.cpp`：本机 HTTP 夹具和协议解析测试。

```sh
cmake -S . -B cmake-build-debug -DBUILD_TESTING=ON
cmake --build cmake-build-debug --target insoulforge_mcp_tests insoulforge_mcp_example -j 4
ctest --test-dir cmake-build-debug -R mcp_client --output-on-failure
./cmake-build-debug/insoulforge_mcp_example
```

交互示例无需命令行参数，输入地址和令牌，按数字菜单查询、调用或退出。
令牌输入会显示，可预设 MCP_TOKEN 环境变量。交互线程等待不会阻塞网络事件循环。
测试服务仅监听本机随机端口，测试结束自动关闭；当前尚未完成官方 SDK 一致性测试。

基础 Client 必须在传入 EventLoop 上串行调用，且对象存活到协程完成。
所有业务预期错误使用 std::expected，工具 isError 不视为网络失败；底层不依赖项目配置、日志或数据库。
后续优先实现增量 SSE、接收阶段限制和取消，再评估会话池与更多协议能力。
